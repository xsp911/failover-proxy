# Политики поставщиков и наблюдения возможностей — v0.21

## Управляемая маршрутизация

В карточке поставщика откройте «Маршрутизация OpenRouter». По умолчанию используется native: запрос не получает дополнительных полей.

В явном режиме openrouter доступны service_tier (default/flex/priority/fast/ultrafast) и точный endpoint slug. Пустое поле не отправляется. Для точного endpoint задаются provider.only=[slug] и allow_fallbacks=false. Это ограничивает маршрутизацию внутри этого поставщика; обычное переключение нашего gateway на другого настроенного поставщика сохраняется.

Настройки администратора применяются на каждой попытке к новой копии тела. Они не переносятся на следующий backend. ZDR, data_collection, max_price и прочие клиентские ограничения сохраняются. При конфликте точного пина с клиентским only/ignore возвращается явная ошибка, список не расширяется. Названия endpoint и доступность тарифов определяются поставщиком: произвольный совместимый API может их не поддерживать.

Настройка проходит API validation, SQLite, редактор и повторное сохранение. Смена режима/tier/pin меняет binding проверки модели; старое verified не является доказательством нового endpoint. Fingerprint и прямой Pelican используют ту же функцию политики. Пулы A6API не получают OpenRouter-поля.

## Пассивные наблюдения

Статистика → «Наблюдения возможностей каналов и контекста» → «Загрузить наблюдения». Это только локальное чтение, не проба поставщика. API: GET /admin/capabilities, доступен администратору.

Хранятся provider/model/protocol/source, идентификатор запроса, запрошенный выход, реально сообщённый usage, reasoning, HTTP/finish/error и хеш политики маршрутизации. Тексты запросов, ответов и ключи не сохраняются. Источники: gateway, fingerprint, pelican. База capabilities.db, права0600; максимум10000записей/30дней. Онлайн-backup включает её автоматически.

HTTP200 с max_tokens означает лишь принятие запроса с этим параметром. Это **не доказанный потолок** и не обещание фактической длины ответа. Значение может быть проигнорировано/ограничено upstream. Наблюдения не изменяют лимиты, маршруты, баны, частоту мониторинга или ответы клиентов.

## Контекст

У каждой модели доступно «Наблюдение контекста»: off либо observe. По умолчанию off; включение только вручную.

observe оценивает UTF-8 текст/4, учитывает тексты сообщений, tools/response_format и запрошенный выход. Бинарные media/data URL не считаются обычным текстом; их реальная токеновая стоимость неизвестна. Это **эвристика, не точный токенизатор и не верхняя/нижняя граница**. Возможное превышение записывается в наблюдение, но не отклоняет запрос и не уменьшает output budget. Серверный400за реальное превышение обрабатывается прежним способом.

Строгий pre-flight по этой оценке намеренно не реализован: он способен отклонить допустимый запрос. Для него отдельно нужны точный токенизатор, учёт media/tools/служебного промпта и подтверждённые окна каждого маршрута.

## Что ещё не реализовано

Парный аудит fingerprint+Pelican одного A6-канала и аккаунтные баны не включены в этот этап. Серверные снимки и измерение изменения пикселей доступны отдельно по явной кнопке у сохранённого SVG; они не оценивают семантическое качество. Текущий Пеликан проверяет явно выбранного поставщика; его нельзя выдавать за атрибутированную проверку конкретного A6 merchant. Автоматические длинные платные пробы не запускаются.
