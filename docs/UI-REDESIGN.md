# Failover Proxy — предложения по переделке интерфейса

**Статус:** согласованный бриф (design brief). Код проекта не изменялся.
**Дата:** 2026-10-28
**Проект:** `xsp911/failover-proxy` (ветка `main`, HEAD `48931f9`)
**Исполнитель:** `anthropic/claude-opus-5.5`
**Автор:** Hermes (анализ кода + рендер всех экранов на мок-бэкенде + сверка с дизайн-практиками)

---

## 1. Коротко

Интерфейс функционально полный и технически аккуратный (vanilla HTML/CSS/JS, без сборки, CSP `script-src 'self'`, 233 `id`, 20 браузерных контрактов). Проблема не в функциях, а в **эргономике**: слишком мелкий шрифт, длинные «простыни» на каждом экране, дубли одного и того же (поставщики — карточками и таблицей), настройки пула — 24 поля в один плоский грид, служебные подписи и предупреждения занимают больше места, чем данные.

Цель: **оператор за 5–10 секунд понимает состояние шлюза и находит нужное действие**, не листая три экрана, и при этом ни одно защитное поведение не меняется (платные подтверждения, ревизии, CSRF, одноразовые токены).

Работа разбита на 5 фаз, каждая — на задачи по 2–5 минут с точными файлами и командой проверки. Всё в `web/`, без изменений backend-контрактов.

## 2. Границы работы

**Можно менять:**
- `web/index.html` — разметка, порядок блоков, новые обёртки и подписи;
- `web/styles.css` — токены, типографика, layout, адаптив;
- `web/app.js` — только рендер-функции и локальное состояние вида (`state`, `pools`, `detector`, `pelican`); ни одного нового fetch-контракта.

**Нельзя менять:**
- `proxy/**` — API, маршрутизация, хранилища, безопасность;
- URL/методы/тела запросов, CSRF, ревизии, подтверждения расходов, одноразовый показ токена;
- `localStorage`/`sessionStorage` (тест `test_scripts_do_not_store_credentials_in_browser` падает), `window.__`;
- внешние ресурсы: шрифты, CDN, `@import`, `url(http…)` — `tools/check-web.py` это валит;
- инлайновые `<script>` и `onclick=` — CSP `script-src 'self'` (см. `proxy/app.py:133`) их заблокирует;
- существующие `id` — по ним живут 20 браузерных контрактов (см. §13).

**Принцип:** сначала разметка и стили, потом поведение. Любой перенос блока — это `id`-совместимый перенос: элементы остаются с теми же `id`, меняются только обёртки и порядок в DOM.

## 3. На каких практиках это основано

Документ не «на вкус»: каждое правило ниже взято из загруженного скилла или локальной базы UX-правил. Колонка «Где» — раздел этого документа.

| Источник | Что именно берём | Где |

| `claude-design` | **Anti-slop**: не делать сетку равновесных иконка-карточек, декоративные цветные полосы на карточках (accent rail), гигантские цифры-монументы, центр-стек. Проверять макет по 10 признакам «AI-слопа» до финала. | §6.1, §15 |

| `design-md` | Никакого raw hex в компонентах — только `var(--token)`; документировать назначение каждого токена; контраст проверять как WCAG-пару. | §7 |

| `ui-ux-pro-max` (chart) | Тренд во времени — линейный график; несколько серий — различимые цвета **и** узоры (не только цвет), заливка ~20%. | §7 |

| `writing-plans` | План = задачи по 2–5 минут: точный файл, точная команда, ожидаемый вывод; никаких «улучшить вёрстку». | §8 |

| `dogfood` | Приёмочный прогон: консоль после каждого шага, пустые состояния, длинный текст, быстрые клики, 375px, скриншот на каждую находку. | §10 |

## 5. Информационная архитектура и архетипы экранов

Правило surface-first: у каждого раздела один главный архетип, остальные — вторичные. Это определяет композицию до выбора цветов.

| Раздел | Архетип | Что это значит на практике |
|---|---|---|
| **Обзор** | Monitor | плотность, «взгляд за 5 секунд», без hero и без равновесных плиток; главная метрика крупнее остальных |
| **Шлюз** (поставщики, модели) | Configure | раскрытие по требованию, видимые save/validation-состояния, минимум декора |
| **Доступ** (ключи, учётка) | Configure | форма + список, одноразовый секрет — отдельным диалогом |
| **Проверки** | Monitor + Inspect | статус сверху, задания и результаты — таблицы с раскрытием |
| **A6API** | Operate | выбор пула и действия доминируют; деньги и состояние — рядом с действием |
| **Пеликан** | Operate + Inspect | одна платная операция, результат и проверки — компактной таблицей |

Навигация (6 пунктов, `Alt+1–6` сохраняется):

```
Обзор            ← KPI, график, состояние маршрутов, последние запросы/ошибки
Шлюз             ← Поставщики · Модели и маршруты · Лимиты
Доступ           ← Ключи клиентского API · Учётная запись
Проверки         ← Мониторинг · Ручная проверка · Задания · Журнал
A6API            ← Пулы · Учётные данные (PAT)
Пеликан          ← Генерация · История
```

Почему:
- «Настройки» — это три разные задачи (маршрутизация, доступ, лимиты). Разделение уменьшает глубину: ключи сейчас — Настройки → Ключи.
- PAT переезжает в A6API: настройка пула и доступ к A6API — один контекст (сейчас раздел пулов прямо отсылает «PAT — в Настройки → A6API», `index.html:405`).
- Журнал становится подвкладкой «Проверок», а не отдельным пунктом меню: `id="tab-detector-log"` остаётся, элемент живёт внутри страницы проверок.
- Хлебная крошка убирается: в `ui-ux-pro-max` крошки оправданы при 3+ уровнях вложенности, у нас два (раздел → подвкладка), и текущий раздел уже подсвечен в сайдбаре.

## 6. Экран за экраном

### 6.1 Обзор (Monitor)

Порядок блоков = порядок вопросов оператора: «жив ли шлюз?» → «что с трафиком?» → «кто виноват?» → «что было?».

1. **Строка состояния** (одна линия): «Система работает · обновлено 14:32 · активных 2 · в очереди 0», справа — период и обновление. Сейчас health-бейдж в шапке, «обновлено» в другом месте, счётчики в футере.
2. **KPI с иерархией, а не четыре равные плитки.** Главная метрика — клиентские запросы (крупнее, 32–36px), рядом компактно: ошибки, переключения, токены, успешность %, p95. Убрать декоративную цветную полоску сверху карточек (`--accent` в `styles.css:88`) — это «accent rail», декор вместо иерархии; цвет оставить только на отклонениях (ошибки > 0, p95 выше нормы).
3. **График активности** на всю ширину (сейчас делит ряд с «Потоками токенов» и сжимается). Токены — компактной полосой под графиком.
4. **Поставщики — одна таблица**, без дублирующих карточек. Колонки: имя, порядок, статус, попытки, ошибки, успешность, средняя задержка, p95, TTFT. Строка раскрывается: IN/OUT, кеш, ток/с, время паузы.
5. **Последние запросы** — сразу под поставщиками; поиск/фильтр/сортировку не трогать (логика рабочая).
6. **Ошибки** — узкой панелью рядом с запросами.
7. «Источники активности», «Наблюдения возможностей», «Прозрачный учёт» — в один сворачиваемый блок **«Как это считается»** внизу. Данные сохранить полностью; первый экран они не занимают.

### 6.2 Шлюз → Поставщики (Configure)

- Компактный список: строка = поставщик (`порядок · имя · URL · статус · [тест] [изменить]`). Клик раскрывает поля.
- **Порядок — кнопки ↑/↓ рядом с номером**, без drag-and-drop. Обоснование двойное: (а) клавиатура и мобильные работают без перетаскивания; (б) чек-лист доступности требует кнопочной альтернативы любому drag-взаимодействию — значит DnD пришлось бы дублировать кнопками, то есть делать ту же работу дважды (`ponytail`).
- Число `priority` остаётся в данных; UI показывает вычисленный порядок `01, 02, 03` и меняет `priority` местами у двух соседних строк.
- Рядом с поставщиком — сколько моделей на него маршрутизировано (сейчас считается только при удалении).
- «Проверить подключение» — в строке, результат инлайн-бейджем.
- OpenRouter-политика (tier/endpoint) — в раскрытии, как сейчас.

### 6.3 Шлюз → Модели и маршруты (Configure)

- Слева список алиасов (поиск + «только включённые»), справа деталь выбранной модели — вместо стопки карточек.
- **Цепочка попыток рисуется явно**: `1 OpenRouter main → deepseek/deepseek-v4.1-flash · 2 A6API relay → deepseek-v4.1-flash-1017`, номера вычислены из `priority`. Выключенный маршрут зачёркнут и помечен «пропускается».
- Ошибки валидации — у поля и бейджем в списке («нет активного маршрута»), а не одной строкой сверху после «Сохранить» (`app.js:755-787`).
- Метаданные (контекст, max output, vision, preflight) — компактной сеткой.

### 6.4 Доступ (Configure)

- Две подвкладки без кнопок сохранения конфигурации.
- Список ключей: имя, префикс, модели (или «все»), запросов, создан, статус; действия «Отключить/Включить», «Забыть». Форма создания сверху, после создания сворачивается.
- Диалог одноразового токена не трогать.

### 6.5 Проверки (Monitor + Inspect)

- Верхняя строка: «Мониторинг включён · следующий запуск 14:50 · порог 95%».
- Таблица целей — компактнее; показывать только отклонения (карантин, ручное отключение), а не два нейтральных бейджа в каждой строке.
- Ручная проверка — одна строка: провайдер, модель, эталон, кнопка «Проверить (3 запроса)».
- Задания и «Состояния маршрутов» — только вёрстка, логику не трогать.
- **Журнал** — подвкладка: таблица + фильтры + «Подробнее».

### 6.6 A6API (Operate)

- **Master-detail**: слева список пулов (имя, модель, статус, участников, расход за сутки), справа деталь с подвкладками «Обзор · Состав · Проверки · Автоматизация · Настройки».
- В карточке пула — **деньги**: «$0.18 за сутки · лимит $5» (сейчас искать в «Автоматизации»).
- Шаги 1-2-3 → **степпер с реальным состоянием**: «Выбор — выполнен · Проверка — 3/5 · Публикация — ожидает».
- «Удалить пул» → в «Настройки → Опасная зона».
- **Форма пула — по секциям** (главное изменение):
  1. *Основное*: имя, модель, эталон, протокол.
  2. *Токены*: рабочий + до 4 тестовых линий (с пояснением, почему тестовый ≠ рабочий).
  3. *Ценовые потолки*: 4 поля USD/1M, подпись «пусто = без ограничения».
  4. *Качество*: порог fingerprint, min cache hit, min success, TTL.
  5. *Отбор*: кандидаты, участники, частота, глубина поиска.
  6. *Бюджеты*: запросы/USD за запуск и за сутки.
  `readPoolPolicy`/`savePool` не меняются — только обёртки и порядок DOM.
- Состав: 7 колонок (`Канал/листинг`, `Продавец`, `Цена вход/выход`, `Кеш`, `Допуск`, `Проверка`, `Похож на модель`), cache hit/успех — в раскрытие строки; `min-width` ~1100px вместо 1450px.

### 6.7 Пеликан (Operate + Inspect)

- Форма в две колонки (провайдер/модель/протокол/effort); таймаут — текст, не `input`.
- Лимиты (16k/64k) — мелкой строкой под effort.
- История — таблица генераций (время, провайдер, модель, статус, длительность, checks), превью — в раскрытии.

### 6.8 Системный слой

- **Сайдбар**: 6 пунктов, без `workspace-switch`; нижний блок короче.
- **Шапка**: заголовок и описание из одного источника (`pageLabels`), без хлебной крошки; health + «обновлено HH:MM» + пользователь + выход.
- **Тосты** — один компонент, 3 варианта; ошибки не исчезают сами (как сейчас).
- **Диалоги** — структуру не менять.

## 7. Дизайн-система: токены, типографика, правила

### 7.1 Токены — три слоя, один источник

Сейчас в `styles.css` два `:root` (старый `styles.css:2` и «semantic» `styles.css:61-69`), а цвета графика захардкожены в JS. Приводим к трёхслойной модели из `design-system`:

```
primitive   --ink-950:#0b0d12; --mint:#70d5b1; --rose:#f29aaa; …
semantic    --bg:var(--ink-950); --text:var(--paper); --accent:var(--blue-soft); --danger:var(--rose); …
component   --button-bg:var(--accent); --chart-requests:var(--mint); --grid-line:#2c3443; …
```

Правила:
- в правилах и в JS — только `var(--token)`, raw hex остаётся **только** в блоке primitive;
- каждый токен имеет назначение (комментарий одной строкой), а не «цвет номер 4»;
- `renderChart` берёт цвета через `getComputedStyle(document.documentElement).getPropertyValue('--chart-requests')`, а не литералы `#63e1bd` (`app.js:469-481`);
- мёртвые правила старого слоя удаляются, а не переопределяются (иначе следующая правка снова «не сработает»).

### 7.2 Типографика

| Роль | Размер | Начертание | Примечание |
|---|---|---|---|
| H1 страницы | 26–28px | 600 | сейчас 27 — ок |
| H2 панели | 15–16px | 600 | сейчас 14 ужато |
| Основной текст | 14px / 1.55 | 400 | база документа |
| Таблицы | 13px / 1.4 | 400, `tabular-nums` | сейчас 11px |
| Вспомогательный | 12px / 1.6 | 400 | минимум на экране |
| Моно (ключи, ID) | 12–13px | 400 | только идентификаторы |

Обоснование: `ui-ux-pro-max` — body line-height 1.5–1.75; мелкий шрифт в таблицах — главная причина, почему сейчас «неудобно». Минимум 12px, 9–10px запрещены.

### 7.3 Layout, состояния, доступность

- Сетка 4/8; панели 12px радиус, контролы 8px; один режим плотности.
- Интерактив ≥ 44×44px на тач-таргетах (кнопки в таблицах — с расширенной областью), видимый `:focus-visible` (уже есть — сохранить).
- Контраст: обычный текст ≥ 4.5:1, границы/иконки/состояния ≥ 3:1. `--muted` проходит, но только при размере ≥ 12px.
- Состояния: default / hover / active / disabled / loading / error — для каждой кнопки и поля; disabled не должен выглядеть кликабельным (сейчас `opacity:.45` — достаточно).
- График: 3 серии — цвет **и** различитель: errors — пунктир, switches — точка-тире (сейчас только цвет и толщина). Заливка области запросов ~20% (уже 22% — ок). Ось и сетка — из токенов.
- Пустые состояния: короткая причина + одно действие («Поставщиков нет — добавить первого»), а не «Загрузка…» навсегда.

## 10. Приёмочный прогон (dogfood)

Перед сдачей — ручной проход по сценариям; на каждую находку скриншот + шаги. Консоль проверять после каждого действия: молчаливые JS-ошибки — самый дорогой класс дефектов.

| Сценарий | Что проверить |
|---|---|
| Холодный вход | логин, восстановление сессии, истёкшая сессия → форма входа с сообщением |
| Пустые данные | нет поставщиков/моделей/ключей/пулов/генераций — понятный текст + действие |
| Длинный текст | имя поставщика 160 символов, URL 2048, префикс ключа — без обрезки критичного, с переносом |
| Быстрые клики | двойной «Запустить проверку» не создаёт второй платный запуск |
| Переключение вкладок при несохранённых правках | предупреждение, правки не теряются |
| Ошибка сети | баннер сохраняется, кнопки разблокированы, повтор не дублирует мутацию |
| 375 / 390 / 768 / 1024 / 1440 | нет горизонтального скролла страницы; таблицы скроллятся внутри |
| Клавиатура | Tab-порядок совпадает с визуальным, `Esc` закрывает меню, фокус не уезжает за экран |
| reduced-motion | анимации отключены, layout не ломается |

Классификация находок (из `dogfood`): Critical / High / Medium / Low × Functional / Visual / Accessibility / Console / UX / Content.

## 11. Что НЕ делать

- Не вводить React/Vue/сборку/Tailwind: проект сознательно на vanilla + статика (`docs/DESIGN.md`, `tools/check-web.py`). Node нужен только числовому детектору.
- Не менять backend-контракты ради удобства UI (никаких новых `/admin/*` эндпоинтов).
- Не «упрощать» предупреждения о том, что fingerprint/Пеликан не доказывают подлинность: текст можно свернуть в `details`, но не удалять.
- Не делать светлую тему, плотный режим, настраиваемые раскладки — не запрос.
- Не трогать `data/`, БД, ключи, `secret.key`; не запускать `*live`-скрипты против продакшена.
- **Не добавлять сущности «на будущее»** (`ponytail`): переключатели вида, темы, конфигурируемые колонки — только если попросят. Удаление дубля лучше добавления режима.
- Не тащить зависимости; никаких новых npm-пакетов в проект.
- Не коммитить. Изменения — в рабочем дереве, отчёт — отдельно.

## 12. Решения по открытым вопросам (приняты)

| Вопрос | Решение | Почему |
|---|---|---|
| A6-креды | **Переносим в раздел A6API**, отдельной подвкладкой «Учётные данные» | пул невозможно настроить без PAT; сейчас UI сам отправляет пользователя в другой раздел (`index.html:405`) |
| Журнал проверок | **Подвкладка «Проверок»**, не отдельный пункт меню | журнал открывается только из проверок и не имеет самостоятельного сценария; шесть пунктов меню читаются быстрее семи |
| Карточки поставщиков на обзоре | **Удалить полностью**, оставить таблицу с раскрытием; переключатель «карточки/таблица» не делать | это 100% дубль одних данных; переключатель — новая сущность без нового сценария |
| Порядок поставщиков | **Кнопки ↑/↓** (и, при желании, ввод числа), без drag-and-drop | работает с клавиатуры и на тач-экранах без дублирования; drag потребовал бы кнопочной альтернативы по доступности |

Если по любому пункту есть возражение — это единственное место, где решение меняется; всё остальное от него не зависит.

## 13. Совместимость: что нельзя сломать

- **233 `id` в `index.html`** — публичный контракт. 20 браузерных сценариев ищут элементы по `#id` (`#pool-jobs`, `#confirm-dialog`, `#pool-name`, `#request-search`, `#journal-detail` и т.д.). Существующие `id` не переименовывать и не удалять; новые — добавлять. При переносе блока `id` остаётся на том же элементе.
- `tests/test_frontend_static.py` требует `tab-stats`, `tab-market`, `tab-detector`, `tab-detector-log`, `tab-pelican`, `tab-settings`, `journal-search`, `request-search`, `journal-detail`, `lang="ru"`, отсутствие `<script type="module">`.
- `test_stylesheet_ready_to_serve_and_motion_accessibility` требует `.workspace-sidebar`, `.chart-tooltip`, `prefers-reduced-motion`, `:focus-visible`.
- `test_scripts_do_not_store_credentials_in_browser` запрещает `localStorage`, `sessionStorage`, `window.__`.
- CSP: `script-src 'self'`, `style-src 'self' 'unsafe-inline'` (`proxy/app.py:133`) — инлайновые обработчики и `<script>` не выполнять.
- Платные действия (`verify/run/restart`, детектор, Пеликан) остаются за `confirmAction`; тайм-аут мутации не считается «не применилось»; ревизии и `preview_id` не обходить.
- Токены показываются один раз (`token-dialog`) — не переносить в список, не логировать.
