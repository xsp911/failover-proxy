## Для чего нужен проект

Failover Proxy объединяет несколько AI-поставщиков за одним адресом API. Клиент использует стабильный алиас модели, а шлюз управляет приоритетами, таймаутами, резервированием и допуском каналов.

**Ключевой принцип — полный ответ до отправки клиенту.** Если upstream оборвал генерацию или вернул некорректный поток, промежуточный текст не утекает клиенту: шлюз может обратиться к следующему поставщику. Успешный JSON или SSE передаётся только после завершения и проверки ответа.

Это отдельный проект, **не форк LiteLLM**. Docker, frontend-сборка и отдельный JavaScript-сервер для обычного запуска не нужны.

> Полная буферизация означает, что клиент не видит токены в реальном времени. Повтор модельного запроса может оплачиваться каждым поставщиком. Уже выполненные клиентом инструменты прокси не исполняет.

## Возможности

| Подсистема | Что умеет |
|---|---|
| **AI gateway** | `/v1/models`, `/v1/chat/completions`, JSON и буферизованный SSE, алиасы моделей, приоритетные маршруты и failover |
| **Контроль нагрузки** | Общий deadline, connect/read timeout, cooldown, ограничение попыток, размеров и параллельности, ограниченная FIFO-очередь |
| **Наблюдаемость** | Клиентские запросы отдельно от upstream-попыток; ошибки, переключения, IN/OUT/cache, TTFT, задержки и p50/p95 |
| **Проверки моделей** | Локальный числовой fingerprint по 63 эталонам, ручные проверки, мониторинг, подтверждение низкой оценки и журнал переходов |
| **Пулы A6API** | Изолированные политики token+model, до четырёх тестовых линий, точная атрибуция канала, бюджеты, отбор, аудит и безопасная публикация |
| **Пеликан** | Один пеликан на велосипеде в одной сцене, явная платная генерация SVG, effort, deadline 5 минут, история и безопасный предпросмотр |
| **Диагностика анимации** | Локальные PNG-кадры и обнаружение движения уже сохранённого SVG, без повторного обращения к модели |
| **Политики поставщиков** | Необязательные OpenRouter `service_tier` и точный endpoint, без переноса параметров между failover-попытками |
| **Возможности каналов** | Пассивный журнал принятых параметров и фактического usage; приблизительное наблюдение контекста без ложного жёсткого отказа |
| **Управление доступом** | Администраторские сессии, CSRF, смена учётных данных, отдельные клиентские ключи и ограничения моделей |
| **Эксплуатация** | Зашифрованные секреты, SQLite online backup, проверка целостности и расшифровки, offline release gate |

## Панель управления

Премиальная тёмная панель на **HTML5, CSS3 и Vanilla JavaScript**. Все рабочие ресурсы локальные: системные шрифты, встроенные SVG-иконки, собственные графики. Нет React, Vue, Vite, Webpack или обязательных CDN.

- **Статистика:** метрики, интерактивный график, поиск и сортировка запросов, состояние поставщиков.
- **Настройки:** поставщики, алиасы моделей, маршруты, лимиты, API-ключи и учётная запись.
- **Проверки моделей:** задания, доказательства проверки, подтверждение и состояние допуска.
- **Журнал проверок:** локальные поиск, фильтры, сортировка и подробности события.
- **A6API:** состав пулов, кандидаты, проверки, публикация, автоматизация и расходы.
- **Пеликан:** параметры генерации, результат, usage и локальная диагностика движения.

Клавиатурная навигация, мобильное меню, reduced-motion и сохранение состояния форм при обновлении данных входят в интерфейс. Браузер не хранит ключи в localStorage/sessionStorage.

## Быстрый запуск

Нужен **Python 3.12+**. Установки Node.js или npm для панели и основного gateway нет в процедуре запуска.

### Linux / macOS

```bash
git clone https://github.com/xsp911/failover-proxy.git
cd failover-proxy
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python tools/run-local.py
```

### Windows PowerShell

```powershell
git clone https://github.com/xsp911/failover-proxy.git
cd failover-proxy
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe tools\run-local.py
```

При первом запуске создайте логин и пароль администратора в терминале. Готовых паролей по умолчанию нет.

| Параметр | По умолчанию |
|---|---|
| Панель | `http://127.0.0.1:8843/` |
| API Base URL | `http://127.0.0.1:8843/v1` |
| Данные | `~/.failover-proxy` |
| Доступ к панели | Учётная запись администратора |
| Доступ клиентских приложений | Отдельный Bearer API-ключ из панели |

Другой порт или каталог:

```bash
python tools/run-local.py --host 127.0.0.1 --port 8843 --data-dir "/absolute/private-data"
```

**Статус платформ:** Linux проверен. Для native Windows подготовлены адаптер файловых блокировок и CI-матрица, но Windows-запуск на текущем Linux-хосте не выполнялся. На Windows используйте защищённый каталог профиля с корректными NTFS ACL. Подробности — в [инструкции запуска](<docs/RUNNING.md>).

### Необязательные backend-функции

- **Числовой детектор** использует Node.js ≥22; без Node панель и gateway запускаются, числовая проверка недоступна.
- **Снимки SVG-анимации** используют отдельный локальный Playwright/Chromium renderer. Это не frontend-сервис. На native Windows этот renderer пока недоступен.
- **A6API** требует собственных учётных данных консоли и тестовых токенов.
- Автоматические платные проверки включаются **только явно**. Открытие панели не означает согласие на генерацию.

## Подключение клиента

Создайте поставщика, алиас модели и клиентский ключ в панели. Затем используйте обычный Chat Completions API:

```python
import os
import httpx

response = httpx.post(
    "http://127.0.0.1:8843/v1/chat/completions",
    headers={"Authorization": "Bearer " + os.environ["FAILOVER_API_KEY"]},
    json={
        "model": "your-model-alias",
        "messages": [{"role": "user", "content": "Привет!"}],
        "stream": False,
    },
    timeout=300,
)
response.raise_for_status()
print(response.json()["choices"][0]["message"]["content"])
```

Основной gateway поддерживает **Chat Completions**. Наличие Chat/Responses в отдельном тесте «Пеликан» не означает, что gateway реализует `/v1/responses` или Anthropic Messages.

## Архитектура

```text
Клиент / SDK
    │  Bearer API-ключ, алиас модели
    ▼
FastAPI · admission · авторизация
    │
    ▼
Маршрутизация → поставщик 1 → резерв 2 → резерв 3
    │             таймауты / cooldown / валидация
    ▼
Полный проверенный буфер → JSON или завершённый SSE → клиент

Локальная панель ── admin API / сессия / CSRF
    ├── конфигурация и клиентские ключи
    ├── статистика и журнал возможностей
    ├── числовой мониторинг
    ├── управляемые пулы A6API
    └── SVG-проба «Пеликан»

SQLite + Fernet ── приватный каталог данных ── проверяемые backup
```

```text
proxy/              Python backend, маршрутизация, хранилища, проверки
web/                Готовые локальные HTML / CSS / JavaScript
 detector/          Встроенные артефакты числового скоринга
 tools/             Запуск, backup, release/security/static проверки
 tests/             Backend и изолированные браузерные контракты
 docs/              Архитектура, эксплуатация, дизайн и ограничения
 third_party/       Лицензии и provenance сторонних компонентов
```

Запускайте **один worker**: admission и cooldown используют память процесса. Для многопроцессного развёртывания нужен общий координатор.

## Безопасность

- HttpOnly/SameSite-сессии, CSRF, origin-проверка и ограничение попыток входа.
- Пароль администратора хранится как PBKDF2-хеш; клиентские API-ключи — как SHA-256. Полный клиентский ключ показывается один раз.
- Секреты поставщиков и A6 PAT шифруются Fernet. Без файла `secret.key` расшифровать backup нельзя.
- HTTPS и публичные upstream-адреса по умолчанию; защита от SSRF/DNS rebinding, redirect запрещён.
- Промпты, модельные ответы и сырые секретосодержащие ошибки не включаются в рабочую статистику.
- SVG считается недоверенным: allowlist-валидация, ограничения размера/сложности, image-only просмотр и отдельная CSP.
- Рабочие данные, токены, резервные копии и runtime-зависимости не публикуются в Git.

> **Для публичного доступа нужен HTTPS reverse proxy и контроль доступа.** HTTP не шифрует пароли, cookie и ключи. Не публикуйте каталог данных и не отключайте TLS-проверку. Renderer с Chromium `--no-sandbox` не является ОС-песочницей; его ограничения описаны отдельно.

## Честные ограничения проверок

**Fingerprint — закрытый рейтинг сходства**, а не удостоверение личности модели. Высокая оценка ближайшего эталона не доказывает подлинность неизвестного upstream.

**Пеликан — поведенческая проба.** Наличие безопасного SVG, множества фигур или движения не доказывает качество канала. Изменение пикселей может быть вызвано одним фоном. Семантическая оценка остаётся ручной.

**Принятый `max_tokens` — не измеренный потолок.** Реестр возможностей различает запрошенный параметр и фактически выданный выход. Эвристическая оценка контекста не используется для безусловного отклонения запросов.

**Резерв расходов — не списание.** Подтверждённые расходы и ожидающие сверки суммы A6API учитываются отдельно.

## Разработка и проверки

```bash
# Готовые локальные ресурсы: проверка без Node и без сборки
python tools/check-web.py

# Python-тесты
python -m pytest -q

# Полный Linux release gate с изолированными browser-контрактами
FP_PYTHON="$PWD/.venv/bin/python" bash tools/check-release.sh --browser-contracts
```

Проверенное состояние v0.22: **929 Python-тестов, 34 подтеста и 20 offline браузерных наборов**. Часть backend-тестов требует необязательных числовых/браузерных runtime. Windows CI подготовлен, но не выдаётся за уже выполненную проверку.

Браузерные тесты используют моки: не требуют реальных ключей и не отправляют платные запросы. Старые `*live`-сценарии не входят в безопасный gate и не должны автоматически запускаться против production.
